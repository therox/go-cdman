# Устройство оригинальной игры

Заметки по восстановлению CD-MAN 2.0 из `CDMAN2.EXE`: где что лежит в
оригинале и как это перенесено. Адреса процедур даны смещениями в сегменте
кода (`L_xxxx`), адреса переменных — смещениями в сегменте данных
(`g_xxxx`).

## Исполняемый файл

`CDMAN2.EXE` (35 337 байт, 08.06.1992) написан на ассемблере. В нём одна
релокация и три сегмента: стек (0x200 байт), данные (`DS` = параграф 20h,
0x3560 байт) и код (параграф 376h, около 20 КБ, около 160 процедур). Векторы
прерываний программа не перехватывает: клавиатура читается через INT 16h,
время — через INT 21h и INT 1Ah, звук — PC-спикер через канал 2 таймера.

Графика — EGA 640×350×16 (режим 10h), меню — текстовый режим 80×25 с
350 строками. Игра пишет в видеопамять напрямую и программирует только
графический контроллер (порт 3CEh) и палитру.

Порт читает сегмент данных из `CDMAN2.EXE` во время работы (лабиринты,
тексты меню, таблицы, мелодии) и проверяет по нескольким строкам, что это
нужная версия. Логика повторяет процедуры оригинала поверх этого массива
байт: `internal/game` хранит сегмент данных целиком (64 КБ, как в реальном
режиме) и обращается к переменным по их смещениям.

## Память

| Адрес | Содержимое |
|---|---|
| `DS:0000–022E` | состояние игрока: лабиринт, CD-Man, монстры, бонусы, таймеры |
| `DS:0233–0272` | очки, жизни, этапы и статистика игроков, время |
| `DS:0466–046E` | экран, круг, признак последнего этапа |
| `DS:0615–061B` | режим игры (один, двое, Double) |
| `DS:1023–102F` | делители для вывода чисел, места очков на табло |
| `DS:1067–106E` | генератор случайных чисел, задержки |
| `DS:165B–1F07` | таблицы рекордов и статистики (= `HIGHSC.CDM`) |
| `DS:2079–24F8` | меню: колонки, подсказки, скорость |
| `DS:254D–3330` | шрифт `CHARTAB.CDM` |

При запуске программа распределяет память DOS: копию `DS:0000–0270`
(начальное состояние, восстанавливается перед каждой игрой), четыре блока
по `0x22F` байт для состояния игроков (`L_0bdb`/`L_0bf5` копируют туда
`DS:0000–022E` и обратно) и буфер файлов. В игре на двоих состояние каждого
игрока хранится в своём блоке и меняется местами при передаче хода.

Видеопамять EGA делится на три страницы по 0x6D60 байт на плоскость:

| Сегмент | Содержимое |
|---|---|
| `A000` | видимая страница: фон этапа (`SCREENn.CDM`) |
| `A6D6` | лист спрайтов `GRAPHICn.CDM` (CD-Man на точке, монстры, бонусы, цифры) |
| `ADAC` | лист `GRAFIXn.CDM` (CD-Man на чёрном, огни); в окно A000–AFFF входят только верхние 119 строк |

Почти всё рисование — копирование байт со страниц 1–2 на страницу 0 через
защёлки (режим записи 1): все четыре плоскости одним `mov`. Поэтому в
порте видеопамять смоделирована побайтно (`internal/ega`): плоскости,
защёлки, режимы записи 0–2 с set/reset, логической функцией и битовой
маской.

## Файлы

**Картинки `.CDM`** (TITLE, SCREEN1–5, GRAPHIC1–5, GRAFIX1–5, WOSHI): 16 байт
палитры EGA, затем изображение 640×350, сжатое RLE. Плоскости идут в
порядке 3, 2, 1, 0, внутри плоскости — по столбцам байт (80 столбцов по 350
строк). Управляющий байт `n`: при сброшенном старшем бите следуют `n` байт
данных, иначе — повтор следующего байта `n & 7Fh` раз. `L_46d9`
распаковывает картинку прямо в видеопамять, ORя каждую плоскость.

**`CHARTAB.CDM`** — 254 символа 8×14, загружаются вторым набором символов
текстового режима (INT 10h, AX=1110h). Режим выбора наборов (AX=1103h,
BL=4) делает так, что символы с ярким цветом берутся из `CHARTAB`, а
остальные — из шрифта видеоадаптера. Из символов `CHARTAB` сложены
логотипы меню и полоска скорости. Шрифт видеоадаптера в порт не входит:
вместо него используется свободный unscii-16 в кодировке CP437, у которого
убраны две строки (`internal/ega/font8x14.go`).

**`HELP.CDM`** — текст справки: строки до CR LF, страницы по 25 строк,
конец — байт 1Ah. Если файла нет, меню сообщает об этом.

**`HIGHSC.CDM`** — дамп `DS:165B–1F07`: таблицы десяти лучших и статистики
текстом, готовым к выводу (с рамками), и двоичные счётчики общего и
активного времени игры. Без файла таблица берётся из программы, в неё
проставляются текущие дата и время. Оригинал записывает файл только при
выходе через Quit.

**`DEMO.CDM`** — запись демонстрации: заголовок до слова с младшим байтом
0Dh, затем слова — код клавиши (как от INT 16h) или 0FFFFh и число опросов
без нажатий; клавиша Esc в записи завершает демонстрацию. Запись
читается при каждом опросе клавиатуры (`L_16b5`), а генератор случайных
чисел засевается числом 12345, поэтому демонстрация воспроизводится
точно.

`XMUSE.BIN` (модуль Protracker «diehard») программой не используется.

## Лабиринт

Лабиринты пяти экранов лежат в сегменте данных текстом: 11 строк по 19
клеток, пробел — проход (`g_048d`). `L_25b8` строит из текста карту клеток
`g_008e`: индекс клетки — 22 + 21·строка + столбец, биты 7–4 разрешают
движение вверх, вниз, влево и вправо, бит 3 — точка, бит 2 — бонус в
клетке, бит 1 — огонь (на него монстры не ступают), бит 0 — проход.
Клетка — 32×24 точки, первая — в (16, 58).

CD-Man и монстры проходят клетку за 8 подшагов: по 3 строки по вертикали
и по полбайта (4 точки) по горизонтали. Положения в полбайта рисуются
отдельными кадрами шириной 5 байт, уходящий фон восстанавливается полосой
шириной 3 строки или 1 байт. Столкновение проверяется по разности адресов
спрайтов в видеопамяти (`L_3c70`).

Монстр на подшаге 7 выбирает следующее направление (`L_27ed`): если
случайный байт больше порога `g_024e`, он идёт к своему CD-Man (синий — от
него), иначе — в случайном порядке направлений. Порог уменьшается на 16 с
каждым пройденным этапом. Развернуться назад монстр может только из
тупика. Монстры 0 и 2 охотятся за первым игроком, 1 и 3 — за вторым
(см. ниже, что из этого выходит в игре одного игрока).

## Звук

`L_2615` вызывается раз за тик: проигрывает очередную ноту текущей мелодии
(слово длины и делители таймера) или, если CD-Man идёт к точке, ноту
«чавканья» по номеру подшага. Нота звучит до следующего тика. Порт
воспроизводит меандр с тем же делителем (`internal/sfx`).

## Время

Всё время игры отмеряется циклами чтения видеопамяти. При запуске
`L_015c` замеряет 640 000 чтений и выбирает число итераций `g_106c` так,
чтобы задержка `L_2682` (`g_106c` × 8 чтений) длилась около 11 мс. Тик игры
(`L_0aac`) — это шаг CD-Man, опрос клавиатуры, нота с задержкой и шаги
четырёх монстров, каждый со своей задержкой: около 80 мс. Меню скорости
меняет `g_106c` на 1/64 за шаг; «Warp» отключает задержки совсем.

Порт считает эти циклы в командах эталонной машины — 2 млн команд в
секунду, при ней калибровка даёт `g_106c` = 1424 и скорость 63 (Normal).
Остальная работа (рисование, логика) учтена приблизительно. Время целой
игры расходится с оригиналом в эмуляторе меньше чем на 0,1%.

## Генератор случайных чисел

`L_4a97`: `seed = seed × 41 mod 65536`, результат — старший байт. Каждые
100 вызовов генератор засевается младшим словом счётчика тиков BIOS
(`L_49eb`), во время демонстрации — числом 12345. `L_4a24` делает два шага
без счёта вызовов (для эффекта растворения заставки).

## Защита от копирования

При первой игре после запуска (`L_4318`) оригинал показывал один из 16
огней и просил ввести его имя из руководства (имена — `g_3397`: CYGN,
DRAC, ORIO…). В имеющемся экземпляре `CDMAN2.EXE` сравнение введённых
букв уже заменено командами NOP. Порт защиту не показывает, но повторяет
её следы в состоянии программы: смену палитры, задержку `g_106a`, номер
огня и один шаг генератора.

## Особенности, которые порт повторяет

- Меню по Esc во время игры сохраняет в буфер те байты страницы 0, которые
  портит текстовый режим, с 16-битным переполнением адреса: после возврата
  первые 64 точки верхней строки берутся из точек 128–191 строки 307. Справка, открытая
  из этого меню, ложится в буфер поверх сохранённого экрана.
- В игре на двоих после того, как первый игрок потерял последнюю жизнь, ход
  к нему всё равно возвращается, и он играет без жизней.
- В режиме Double при проверке «впереди второй CD-Man» на ветке `L_35e6`
  регистр BX после стены содержит номер подшага, а не номер другого
  игрока, поэтому первый CD-Man может войти во второго.
- Монстры 1 и 3 целятся во второго игрока, а в игре одного игрока его
  координаты не обновляются и остаются нулевыми, так что, «преследуя»,
  эти двое идут к левому верхнему углу лабиринта.
- Съеденный монстр возвращается на начальное место монстра 0 с его же
  начальным направлением.
- Съеденный огонь прерывает обход огней в этом тике.
- При выходе монстра из клетки на подшаге 7 цикл `loop` с CX=0 делает
  65 536 пустых итераций.
- Кэш палитры `g_1032` не сбрасывается при смене видеорежима.

## Отладочный режим и сверка

`-script файл` запускает игру без окна в виртуальном времени (полночь
1 января 1992 года, как у эмулятора). Строки сценария имеют вид
`<секунды> <команда>`, где команда — одна из:

- `key <клавиша>` — нажатие (`space`, `enter`, `esc`, `up`, …, или символ);
- `shot <файл.png>` — снимок экрана;
- `tickkey <номер тика> <клавиша>` — нажатие в начале указанного тика;
- `keyhook <адрес> <клавиша>` — нажатие при входе в процедуру `0992`
  (мигание «Player»), `1BFD` (ожидание под таблицами) или `1DCF` (ввод имени);
- `poke <адрес> <значение>` — записать слово в сегмент данных;
- `levelpoke <адрес> <значение>` — то же перед каждым этапом;
- `quit` — завершение.

Дополнительные флаги:

- `-debug-seed` — генератор всегда засевается числом 12345, игра
  становится детерминированной;
- `-debug-screen N` — игра начинается с экрана N (как переменная `g_027b`);
- `-debug-state файл` — писать состояние в начале каждого тика;
- `-wav файл` — записать звук прогона.

Именно этим режимом порт сверялся с оригиналом. `CDMAN2.EXE` исполнялся в
эмуляторе 8086+EGA с теми же нажатиями (пересев генератора подменялся
константой), и в начале каждого тика сравнивались `DS:0000–0271`,
избранные переменные, контрольная сумма всего сегмента данных и видимой
страницы. Совпали демонстрация целиком, игры одного игрока на каждом из
пяти экранов, прохождение всех 15 этапов, игры на двоих и Double до конца,
меню по Esc с «Position» и «Continue»; снимки всех экранов меню, справки,
таблиц и ввода имени совпали попиксельно. Расходятся только счётчики
игрового времени, зависящие от часов.
